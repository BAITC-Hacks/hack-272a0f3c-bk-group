Проверки интерфейса исполняют поставляемый JavaScript с управляемыми ответами сервера. Дополнительно выполнены сценарии в настоящем браузере, описанные ниже. Это разные уровни проверки; число автоматических тестов не обозначает число ручных сценариев.

Ранний дефицит до возможного прихода проверяется отдельно.

## Исправления

| Сложный случай | Исправленное поведение |
| --- | --- |
| Дробные метры, упаковки 0,1, потребность 0,0004 | Денежная и складская арифметика не опирается на округлённые графики. Машинная погрешность не добавляет упаковку, малая потребность не исчезает. |
| Резерв превышает остаток, завтра большой приход | Уже существующий дефицит отмечается на дату среза. Будущий приход не скрывает проблему. |
| Приход с временем, поставка за пределами горизонта | Учитывается календарный день. Поставка за пределами горизонта не уменьшает текущую потребность. |
| NaN, Infinity, отрицательные резервы, неизвестные входы | Некорректные значения отклоняются или блокируют соответствующую позицию. Они не превращаются в нулевой безопасный заказ. |
| Повторная загрузка архива, копии книг и строк | Дубли отклоняются или требуют сверки. Скопированные поставки не удваивают доступный товар. |
| Повреждённый ZIP, неполная схема, чрезмерное распакованное содержимое | Понятная ошибка до публикации новых данных. Предыдущий успешный расчёт сохраняется. |
| Незнакомый поставщик, ведущие нули в SKU, разделители в кодах | Источник не переименовывается в известного поставщика. Код сохраняется, ключи разных товаров не сталкиваются. |
| Повтор номера накладной в другой день или году | Покупки анализируются отдельно. История покупателей не восстанавливается. |
| Большие партии и упаковки | Повторяющиеся объёмы сохраняются в спросе; дробная минимальная партия округляется корректно. |
| Экспорт дробей и опасных текстовых ячеек | XLSX показывает малые ненулевые количества; CSV не исполняет текст как формулу. Заблокированные позиции не попадают в проекты заказов. |
| Две вкладки меняют параметры, остатки, товар или документ | Сервер сверяет версию и экземпляр расчёта. Устаревшее действие отклоняется до записи. |
| Двойное проведение, конкурирующие продажи или выплаты | Только одна допустимая транзакция проходит; нет повторного движения, перепродажи или отрицательной кассы. |
| Отмена прихода после расходования, перемещения или производства | Отмена, создающая отрицательный остаток, отклоняется целиком. Частичного отката нет. |
| Будущая дата складского или денежного документа | Документ остаётся черновиком до допустимой даты. Заказы и счета без движений можно планировать. |
| Запись успешна, последующее обновление страницы не удалось | Интерфейс сохраняет подтверждённый результат, закрывает старые действия и предупреждает о неактуальных остатках до успешного обновления. |
| Сбой сохранения настроек или повреждение кэша | Параметры и журнал сохраняются одной транзакцией. Новый отчёт не публикуется при ошибке записи; повреждённый кэш пересоздаётся из исходников. |
| Перезапуск сервера, поздний ответ карточки или AI | Обновляется нужная версия данных; закрытая карточка не открывается снова, ответ старого контекста не подменяет новый. |
| Тайм-аут и некорректный ответ AI-провайдера | Сообщение об ошибке без утечки ключа, сохранение вопроса и восстановление кнопок. Проверено с имитацией ответов, без внешних запросов. |
| Равные ошибки моделей при расчёте среднего | Сохранён исходный порядок арифметики: защита от переполнения не меняет историческую ничью моделей из-за одного машинного разряда. Отдельно проверено среднее для конечных значений 1e308. |

## Проверка через сайт

Синтетические данные и документы помещены только в `data/qa-site/`, отдельный сервер запускался через `scripts/qa_server.py`. Эти данные явно помечены QA и не используются как результат компании. Исходные архивы не изменялись, клиентские идентификаторы не создавались.

В браузере проверены:

- Пагинация 73 товаров, поиск с пробелами, фильтры и карточки дробного товара и товара с отрицательным свободным остатком.
- Ручное уточнение остатка с причиной, пересчёт и изменение статуса товара.
- Исторический прогон на тестовом наборе, затем загрузка другого архива: старая история очищается.
- Повреждённый архив: видна ошибка, последний успешный отчёт доступен, новый пересчёт работает.
- Перезапуск сервера и восстановление страницы, блокировка повторного запуска во время расчёта.
- Приход → производство → продажа → недостаточная выплата → исправление → проведение → отмена → возврат. Итоговые остатки и деньги сверены.
- Две вкладки с разными версиями черновика и цены товара: устаревшие проведение и сохранение отклонены, новая цена сохранена.

Подробная сверка документов и состояний: [docs/JOINT_QA.md](docs/JOINT_QA.md).

## Реальные архивы и экспорт

Загружены 10 книг из двух исходных архивов: каталог содержит 3 667 SKU (2 943 IEK и 724 Systeme Electric). В отчёте видны 33 некорректные строки продаж; полных дублей продаж — 0. У 113 позиций единица измерения неизвестна. Ошибки исходников не замаскированы нулями.

Через HTTP скачаны XLSX и ZIP. В обоих планах 3 667 строк. С исходным отчётом сверены 7 883 числовые ячейки, включая 4 332 дробных значения; у 1 114 артикулов сохранены ведущие нули. В XLSX нет формул, навязанных исходными текстовыми значениями. При неподтверждённых бизнес-настройках готовых заказов 0: CSV по поставщикам содержат только заголовки, как и должно быть. Проверка малых количеств 0,0004 и 4e-7 отдельно выполнена на синтетическом XLSX с визуальным просмотром.

Машинный протокол: `outputs/qa-real-export/verification.json`. Экспорты сохранены рядом; они не меняют настройки, архивы или складской учёт.

В рабочий каталог учёта через интерфейс импортированы 3 554 реальные карточки; 113 позиций без единицы измерения пропущены. Проверено отсутствие документов, движений запасов, контрагентов и тестовых SKU в рабочей базе. Денежный баланс — 0,00. Цены и начальные остатки требуют ввода по фактическому учёту.

На окончательной версии через сайт повторён период июль 2024 — август 2026: 32 025 проверенных сочетаний «товар–месяц», 39 944 неизвестных факта и 6 291 случая короткой истории исключены. Скрипт `scripts/verify_selector_results.py` прошёл: все 128 100 прогнозов сохранённых базовых методов совпали с эталоном; 32 025 прогнозов текущего алгоритма и 27 групп симуляций совпали с независимым расчётом. Эталонные данные и допуски сравнения не менялись.

После последнего перезапуска подтверждены `busy=false`, `loaded=true`, `error=null`, сохранность каталога и выключенные бизнес-подтверждения. Итоговый протокол: `outputs/final-site-verification.json`; протокол независимой сверки: `outputs/selector-evaluation/production-verification.json`. Временный QA-сервер остановлен; рабочий адрес остаётся один — 8765.

## Границы готовности

Найденные воспроизводимые ошибки исправлены, перечисленные проверки пройдены. Это не доказательство отсутствия любых ошибок и не нагрузочное тестирование публичного многопользовательского сервиса.

- Для реального заказа нужны подтверждённые сроки, резервы, упаковки, входящие поставки и свежие остатки. Подтверждения компании не включаются автоматически ради демонстрации.
- Результаты исторического сравнения относятся к прогнозу месячных продаж. Полной истории закупок и ежедневных stockout нет; доказанная экономия компании не заявляется.
- Возвраты пока ручные, без автоматической связи с исходной продажей и ограничения возвращённого количества. Прошлая дата документа не восстанавливает исторические остатки; движение меняет текущий баланс при проведении.
- Операционные складские остатки и расчёт по архивам пока отдельны. Импорт каталога переносит только карточки, без остатков, денег или документов.
- Приложение работает локально, без ролей сотрудников, фискализации, банковского обмена и синхронизации с маркетплейсами.
- Настоящие ответы платных AI API не проверялись. Проведены проверки отказов и контекста с имитацией провайдера.

Следующий этап проверки качества прогноза — новые месяцы, ещё не использованные при настройке алгоритма, и фактические датированные поступления/резервы компании. Уже изученную историю нельзя считать независимым доказательством превосходства модели.

## Уточнение интерфейса после обратной связи

Пустой список ближайших задач показывает «Ожидание новых задач». Происхождение импортированных карточек видно в сводке, каталоге и CSV. Журнал показывает одну итоговую запись импорта; исходные 3 555 событий аудита сохранены, последующие изменения импортированных товаров остаются видимыми. Фильтрация выполняется до ограничения списка в 200 событий, поэтому массовый импорт не скрывает более раннюю ручную работу.

Начальная страница выбора режима убрана. На входе открывается рабочее пространство. Неподключённый AI скрыт; при готовой конфигурации провайдера доступна кнопка помощника. Проверены настроенный провайдер, отсутствие настройки и ошибка проверки конфигурации.

После этих правок прошли 183 теста приложения и 18 проверок JS учёта. В браузере на рабочей базе подтверждены: 3 554 карточки с источником «План закупок», одна видимая запись импорта, новый текст пустых задач, отсутствие неподключённого AI в навигации и отсутствие ошибок консоли. Реальные карточки, документы и исходный аудит не изменялись этим обновлением.
